# Lean formalization of Stephen Dolan's *mov is Turing-complete*

The central computational result of Stephen Dolan's 2013 paper is fully proved
in this repository, including the four-register reduction. It has its own
theorem and supporting modules; it can be read without following the pure-SMC
proofs. The paper is credited as a source with relationship `formalizes` in
[formalization.yaml](formalization.yaml).

Paper: [author's PDF](https://www.cl.cam.ac.uk/~sd601/papers/mov.pdf),
[university-hosted PDF mirror](https://harrisonwl.github.io/assets/courses/malware/spring2017/papers/mov-is-turing-complete.pdf).

## Main theorem

[`SmcTuring.Dolan.Four.four_register_mov_certified_simulation`](SmcTuring/Dolan/FourStopping.lean)
constructs one fixed program with exactly four available registers and the
three instruction forms: immediate load, indexed load and indexed store.
For every finite Turing machine and finite input, its generated initial state
satisfies both:

```text
MOV loop halts     ↔ source Turing machine halts
certified zero trap ↔ source Turing machine halts
MOV loop diverges  ↔ source Turing machine diverges
```

The body is independent of the simulated machine and input, which are encoded
in initial data memory. Repetition supplies one unconditional backedge. The
code remains static. The abstract model has unbounded memory and addresses;
an invalid dereference traps, including attempting to use offset zero as a
cell address. Section 5 of the source explicitly stops by reading invalid
address zero. Invalid reads do not successfully return zero. `ZeroTrapHalts`
constructs the successful compiled prefix ending immediately before the actual
load with zero base and zero offset, and proves that load traps. Initialization is defined from the machine and input without
an oracle for future execution.

The intermediate theorem
[`SmcTuring.Dolan.Mov.fixed_mov_simulation`](SmcTuring/Dolan/Simulation.lean)
constructs a 64-MOV body using thirteen logical registers. A proved scratch-ring
compiler lowers it to the four-register body, whose length is proved to be
2,252 MOV instructions. This is the witness generated by this formalization,
not an instruction-count claim about the paper's printed listings.

## Exact scope and source corrections

This proves the paper's computational construction with the disclosed local
corrections and model adaptations recorded as D01-D05 in
[ERRATA.md](ERRATA.md#d01-d03-dolan-source-corrections-to-audit-in-the-foundation).
Those notes are formalization corrections, not author-approved published errata.

- D01-D03 repair the preserved stack value, halt selector polarity and
  scratch-register index used when spilling a result.
- D04 uses a computably initialized two-sided tape rather than the printed
  empty-left-stack initialization.
- D05 checks the sentinel before dereferencing a candidate, handling empty
  transition lists as well as exhausted scans.

The full computational argument is checked. The conclusion concerns the
normalized abstract construction, with these adaptations explicit; the printed
assembly is not claimed to execute correctly byte for byte. Section 7's
historical discussion and hardware design suggestions are outside the theorem.
Finite x86 hardware is not claimed to have unbounded storage.

The word encoding distinguishes valid `.address 0` scratch storage from the
invalid pointer `.offset false`. Valid cell `c` can be normalized to the even
positive numeric address `2 * (c + 1)`; the two offsets are zero and one. The
ring compiler shifts heap cells by 13 and preserves the invalid-zero tag.

supplies its credited Lean formalization with the stated corrections.
